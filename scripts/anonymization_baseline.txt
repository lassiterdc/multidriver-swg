# Accepted anonymization findings — THE LEDGER IS NOT HERE.
#
# The acceptance ledger lives in the private companion repo beside the carrier,
# because a row cannot be written without the very string it accepts and this
# repository tracks none. Rows there are keyed by carrier ORDINAL rather than by
# token text, so the loaded token set and the ledger cannot disagree. This file
# records WHY acceptances exist; it is not itself a ledger and defines no rows.
#
# The hash in a row pins the acceptance to the LINE CONTENT, not to a line number.
#   - Editing anything ELSEWHERE in the accepted file does not disturb it.
#   - Editing the ACCEPTED LINE ITSELF voids it: the guard goes red again.
#   - A row whose line no longer matches is reported as STALE and fails the guard,
#     so the ledger cannot accumulate entries that protect nothing.
#
# R32: non-sensitive personal detail is TOLERATED. Credentials, tokens, keys and
# environment-file contents are NEVER tolerated and are never accepted.
#
# Two acceptances are live at the time of writing and both lapse on their own
# schedule rather than being remediated here. One is a generator-owned answers
# file whose in-file remediation is reverted by the next template update, so the
# durable fix is upstream — referencing the template through its public URL. The
# other is a frozen upstream snapshot whose value is a byte-identity provenance
# claim that editing the line would falsify; it lapses when the refactor deletes
# the directory, at which point its rows go stale and the guard says so.
