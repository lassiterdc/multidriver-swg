# Changelog

## [Unreleased]

### Added

- A `multidriver-swg` console command (also `python -m multidriver_swg.workflow`) starts a run from one main configuration file; it runs the pre-run checks, writes the run-start record and starts the engine, reporting one of three exit bands (0 completed, 3 started and not completed, 2 refused to start), and it constructs the engine's environment rather than inheriting it.
- Three launch bindings, all wired: `local` and `batch_job` start the engine on this host, and `1_job_many_srun_tasks` writes `engine_batch.sh` into the run output and submits it with `sbatch --wait --parsable` as one allocation; the submission's band is read from its job id and exit — no id is 2, an id with exit 0 is 0, an id with any non-zero exit is 3 — and its engine output is captured in a per-attempt log in the run output, so a lock refusal prints the same unlock invocation the engine path prints without the command ever clearing the lock.
- The run's report is a field of the rule table: a row declares which of its outputs the report shows and the heading each appears under, the workflow file flags those outputs for the engine's report, and the citation section is the one item the graph declares today. An item is refused unless it names a declared output once and carries a heading, and unless its file is one a browser displays — HTML or an image — so an artifact meant to be read in the page cannot silently become a download button.
- A run now closes with one output-bearing final rule: `end_of_run` waits on every other target of the run's list and writes the record directory `end_of_run/record`, and the run's target list therefore carries that record as its last entry in every branch. The rule is local, so it runs where the engine's metadata store is, and its output is a directory so a second invocation that finds everything up to date does not run it again.
- The record carries the divergence report — a text file and an HTML rendering of it — only when the run selected the legacy side of a registered pair: a run whose every pair ran its current side has diverged from nothing, so its record holds neither file. The HTML file is the run's divergence report item, shown in the engine's report under `Divergence report`.
- The record always carries `provenance.json`: the exercised set and the implementation identity each producer persisted, read from the engine's own metadata over the end-of-run rule's input list, so a run that ends with fewer targets names exactly the producers of those targets. The set is cumulative (an output kept from an earlier invocation counts its producer), and the file is refused, naming the producer, when a producing rule's identity is missing or names another system. The file also lists which rules ran in this invocation, read from each record's end time because the engine's start time is null in every local record at the version measured, and carries the run's side record unaltered. Its seeds are empty: no producer draws and no persisted form of a seed exists yet.
- A release now runs the whole test suite at the tagged commit and refuses the tag unless that run was whole, complete and passing on `main`, with both source files recording the tagged version; nothing is built or uploaded until that gate passes.
- A push to `main` now gets a `Main tag check` run that waits sixty minutes and then reports whether the pushed commit carries a tag: it names every tag that carries it, or prints the commit and a warning annotation when none does and appends the sentence to the run's step summary, and it fails nothing.
- The release's `post-build-check` job now checks out the tagged commit before it downloads the artifacts, enumerates the bytes the release ships — the sdist, the wheel and the commit's source archive, every member with its digest, beside the identity of the whole-suite run the gate read — compares that record against `release_state.toml`, refuses the release when a shipped file is of a class the table declares excluded or estate-resident or is in two classes at once, and keeps the record as a `release-enumeration` artifact.
- A release that uploads now ends with a GitHub Release for the tagged version carrying that byte record as an asset, with the asset's `sha256` and the release's three licence statements in the notes, and a workflow dispatched by hand records the release's version DOI and its archived revision and directory in `CITATION.cff`, keeping the enumeration beside them under `releases/{tag}/` — all committed to `develop` once the deposit and the archive have the identifiers.
- The release now checks its licence statements against the bytes it ships: `post-build-check` holds each artifact's `License-Expression`, each byte set's covering `LICENSE`, the README and `CITATION.cff`'s `license` against the licence `release_state.toml` records, refusing the release on a disagreement before the enumeration is kept, and the dispatched identifiers workflow fails its run when the deposit's licence field states another licence than the release does.
- The package root now declares its public API as `__all__`, the seven modules and subpackages it carries, and `scripts/check_public_api.py` reads that list and each listed subpackage's own list out of a built wheel and refuses four classes of drifted surface; the placeholder `hello()` is gone, `README.md` and `docs/usage.md` describe the declared surface instead of the placeholder, and `__version__` stays as it is because the `--version` command reads it.
- One content scanner, `scripts/content_scan`, now answers every question the two guard jobs ask. It reads the tree once, holds the corpus, the skip markers, the count-only report form and the exit codes in one place, and carries a class each for private identifiers, machine paths, planning references and public secret shapes. Both guard jobs keep the job id the repository ruleset requires, run on every branch and on every tag push, and report counts only. A push reports the secret class's count and refuses nothing on it; an identifier, a machine path or a planning reference still fails the job that owns it.
- The release's `post-build-check` job now holds a release to its lock, in order: it installs `uv` at the version the lock was rendered under, installs and imports each built distribution into a fresh environment holding only that artifact, compares the committed `pylock.toml` and `requirements.txt` against a fresh rendering of the declaration at the recorded cutoff, refuses a release whose sdist does not list both lock files, and reads the enumeration's `whole_suite_run` back against the identity the release gate published; the Whole suite job installs its runtime stack from that lock under `--require-hashes`, so the versions it tests are the bytes the release ships.
- The package's runtime declaration is now the set its own imports name, `numpy>=2,<3`, with `pandas` and `xarray` left to the test environment; a new `Install check` run on every push builds the sdist and the wheel and `scripts/check_install.py` installs each into a fresh environment holding only that artifact, imports every module it provides and reads every import statement it carries, refusing an artifact that will not install, a module that will not import, a versionless declaration, an import of a distribution nothing declares and a declared distribution nothing imports — once at the highest resolution a user's install gets and once at `lowest-direct`, so the floor is installed rather than stated.
- The rule table now holds fifteen rows over the same twelve systems: the observed-record system owns three rows before the merge (`observed_record_pre_selection`, `observed_record_licence` and the merge row `observed_record_assembly`, whose name and output are unchanged) and the combined-event-identification system owns two (`per_source_event_selection` and the existing row). The licence row is the table's one checkpoint (`RuleSpec.checkpoint`), and a rule is addressed by its name through `rule_named`.
- A run now stops after the licence when the selection lacks a fit the licence requires: a new `ruling_stop` module holds three pure functions (`required_entries`, `missing_entries`, `stop_targets`), and the workflow file derives `all`, `end_of_run` and the attribution row's inputs from one function evaluated after the licence checkpoint, so a stopped run still builds the attribution row and its end-of-run record, exits 0, and a second run with the fit added continues from the merge without re-running the rules before it. The stub licence writes its requirement from `stubs.LICENCE_REQUIRED_ENTRIES`, empty in the shipped graph, so the shipped graph never stops.
- Version stacking: a run at a new toolkit commit can rebuild chosen rules and keep the others. A new optional `[version_stacking]` table in the main configuration holds `rerun_rules` (rule names the command passes to the engine as `--forcerun` in `local`, `batch_job` and `1_job_many_srun_tasks`, refused by the pre-run step when a name is not a rule of the table) and `allow_mixed_versions` (false by default). The end-of-run step now refuses a system whose rules persisted unequal implementation identities, naming two of its rules, both identity files and `allow_mixed_versions`, and with the override it records every rule's identity. The run-start record gains `allow_mixed_versions` and is now `run-start:2`, and `provenance.json` gains `rule_identities` and `mixed_systems` and is now `end-of-run-provenance:2`; a record or file of the previous form is refused, so a run left half-done by an earlier version is started again.

### Removed

- `scripts/check_anonymization.py` and `scripts/check_planning_references.py`, with the three test modules that pinned them, are gone: their behaviours live in the content scanner and its tests, and both guard jobs and the commit hooks all call that scanner.
- `rule_for_system` and the pre-run step's private `_rule_for_name` are gone, replaced by `rule_named`, which returns the one row of a rule name and refuses an unknown name listing the names the table holds; a system may now own several rows, so no lookup by system exists. `RuleSpec.local`, a field no renderer read, is gone with them.
